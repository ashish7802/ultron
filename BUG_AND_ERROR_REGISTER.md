# ULTRON Bug and Error Register (Phase 1 Baseline)

All defects below were reproduced or verified directly from source code and live execution in this environment.

| ID | Severity | Location | Symptom / Failure Mode | Root Cause | Planned Fix |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **BUG-001** | **CRITICAL (Security)** | `/app/api/learning/route.ts:55-58` | An unprivileged `operator` (`CHAT_AUTHENTICATED`) desktop session can approve, activate, and rollback learning evolutions restricted to `founder`. | `isLearningAuthorized()` hardcodes `return { authorized: true, role: "founder" }` whenever `validateDesktopSession(nextReq)` succeeds. | Return the actual session role (`desktopVal.session?.userRole \|\| "operator"`) and require verified `founder` (`FOUNDER_AUTHORIZED`) identity for privileged actions. |
| **BUG-002** | **HIGH (Honesty / Security)** | `/components/SecurityDashboardModal.tsx:820-833` | UI displays `"Synaptics VFS7552 Touch Sensor"`, `"Synaptics Incorporated"`, `"Available"`, and `1 fingerprint(s)` even when Windows Hello is unavailable or unsupported (e.g., Linux or hardware without sensor). | Hardcoded fallback JSX strings used when `windowsHello` fields are null/missing. | Render truthful `"Unavailable"` / `"Not detected"` / `0` values strictly derived from backend `windowsHello` verification response. |
| **BUG-003** | **HIGH (Runtime / Tests)** | `/ultron_engine/computer/desktop_engine.py:30-38`, `/ultron_engine/computer/computer_intelligence_cli.py:39` | `npm test` (`scripts/test_milestone5_battery.cjs:120`) fails with `AssertionError: false !== true` and writes `ULTRON_EMERGENCY_STOP.lock` on exit. | Unconditional top-level `import winreg` and `ctypes.windll` in `desktop_engine.py` crashes `computer_intelligence_cli.py` on non-Windows hosts before `emergency_stop_status` can run; `safetyControls.ts` fails closed (treats as locked), causing `write_file` to be rejected and the test's `finally` block to persist a false emergency lockfile. | Guard Windows-only imports (`winreg`, `ctypes.windll`) in `desktop_engine.py` and `input_driver.py` (or lazy-load Windows modules in `computer_intelligence_cli.py`) so cross-platform commands (`emergency_stop_status`, `trigger_emergency_stop`, `reset_emergency_stop`, `os_info`) execute cleanly while Windows-only UI commands return explicit `Unavailable on non-Windows platform` errors. |
| **BUG-004** | **HIGH (Security)** | `/app/api/tts/route.ts`, `/app/api/transcribe/route.ts`, `/app/api/wakeword/route.ts` | Unauthenticated external or cross-origin requests can trigger PowerShell TTS execution, Python subprocess spawning, or disk writes for audio uploads. | Missing `validateDesktopSession()` and origin/CSRF checks on all three voice routes. | Enforce `validateDesktopSession(req)` on GET/POST/DELETE handlers while preserving `lib/audioUpload.ts` bounded stream validation. |
| **BUG-005** | **HIGH (UX / Runtime)** | `/components/UltronChat.tsx`, `/components/SecurityDashboardModal.tsx`, `/components/TaskOrchestrationModal.tsx`, `/components/LearningEvolutionModal.tsx` | Browser-blocking `window.alert()`, `window.confirm()`, and `window.prompt()` calls fail silently or throw inside sandboxed iframes / Electron overlays and block execution. | Legacy modal handlers relied on native browser dialogs instead of React UI state. | Remove 100% of `window.alert`, `window.confirm`, and `window.prompt` calls; replace with accessible inline confirmation drawers, banners, and toast notifications. |
| **BUG-006** | **MEDIUM (UX)** | `/components/UltronChat.tsx:346-368` | Global `keydown` listener steals keyboard focus back to the chat composer when typing inside Security, Orchestration, Learning, or Dashboard overlays. | `handleGlobalKeyDown` only checks `!isMemoryModalOpen` and ignores all other active views/modals and form inputs. | Scope keyboard focus strictly to the active Chat view when no input/textarea/select/dialog is focused. |
| **BUG-007** | **MEDIUM (Feature Gap)** | `/components/CommandCenterDashboard.tsx:523,642` | Clicking Settings displays `"Settings are not available in this build."` | Settings screen and `/api/settings` backend were never implemented. | Build complete persisted `/api/settings` backend and full 9-section Settings Center UI. |
| **BUG-008** | **MEDIUM (Feature Gap)** | `/app/api/chat/route.ts:62` | Switching Ollama models or adjusting endpoint/temperature at runtime is impossible without restarting the server and changing env vars. | `OLLAMA_MODEL` and `OLLAMA_BASE_URL` are read statically at module initialization. | Introduce `/lib/runtimeConfig.ts` + `/api/models` so active model, endpoint, timeout, and temperature are dynamically configurable (with loopback SSRF protection) and respected by `/api/chat`. |
| **BUG-009** | **MEDIUM (Security)** | `/app/api/security/auth/route.ts`, `/app/api/security/emergency/route.ts`, `/app/api/security/policies/route.ts` | Unauthenticated GET callers can enumerate active session metadata (`sessionId`, `deviceId`, `userId`) and query emergency/policy endpoints without loopback/origin validation. | `GET /api/security/auth` returns `activeSessions` unconditionally; `emergency` and `policies` GET handlers perform no origin/session check. | Restrict `activeSessions` details to authenticated sessions and enforce loopback/session validation on GET endpoints. |
| **BUG-010** | **MEDIUM (Portability)** | `/lib/screen/screenCaptureEngine.ts:53` | Screen capture driver fails to locate Python on Linux/macOS environments where only `python3` exists. | `_resolvePython()` falls back to hardcoded `"python"` instead of shared `resolvePythonExecutable()`. | Delegate `_resolvePython()` to `resolvePythonExecutable()`. |
| **BUG-011** | **LOW (Test Harness)** | `/scripts/test_phase2_battery.cjs` | Reports `9 / 13 tests passed (100%)` and exits with code `0` despite 4 failing assertions (including vault CRLF/LF hash mismatch on Linux). | Summary logger hardcodes `(100%)` and does not set non-zero exit code on failure. | Document baseline test discrepancies honestly; preserve vault immutability and ensure new test suites exit non-zero on any failure. |
| **BUG-012** | **LOW (Lint Debt)** | Multiple legacy `.cjs` and `.ts` files | `npm run lint` emits 93 warnings (unused vars, `@typescript-eslint/no-require-imports`, etc.). | Legacy test scripts and older modules lack strict cleanup. | Ensure all newly created and modified files pass `npm run lint` with zero errors and zero new warnings. |
